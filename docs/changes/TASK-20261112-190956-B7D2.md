## Objetivo

Que el operador del piso pueda **leer el código de barras de la OT con el teléfono**, iniciar
una operación y finalizarla, con el **ciclo por pieza** calculado y pintado en el momento. Sin
capturar nada a mano, sin login (etapa posterior) y sin tocar el plan.

## Tercer ajuste (misma fecha): sin límite de ancho

El usuario reporta «los laterales en blanco». La hoja tenía `max-width: 560px` que en una
tablet (820 px de ancho) dejaba 130 px de margen a cada lado. Se eliminó el `max-width` y el
marco de escaneo se agrandó (`min(92vw, 55vh, 700px)`). Contenido comprobado a 820 y 1024 px
de ancho.

Reporte del usuario con captura del teléfono: «al leer la OT está muy chico el texto, ya que
lo leyó no necesito ver la cámara, necesito ver los datos», y si la adaptación aplica a las
demás pantallas. Se registra como **RULE-PRD-009**.

- `src/web/prd/prd.css`: `.pantalla-hoja` pinta `var(--fondo)` opaco y `.hoja` ocupa la
  pantalla (`flex: 1 1 auto`, sin radio, sin `backdrop-filter`); OT `clamp(3rem, 16vw, 4rem)`,
  datos `clamp(1.2rem, 5vw, 1.5rem)`, cantidad `clamp(2.4rem, 12vw, 3rem)`, ciclo
  `clamp(3rem, 15vw, 4rem)`; `.datos > div` en una columna; `.acciones` `position: sticky` al
  pie; `.hoja > * { flex: 0 0 auto }` para que nada se aplaste cuando el contenido no cabe;
  se ocultan las flechitas del `input[type=number]`. La pantalla de escanear sube su texto
  (h1, pista, estado, aviso sin cámara) pero conserva la estructura: es la única que necesita
  el video.
- `src/web/prd/index.template.html`: el error y el enlace «Iniciar otra operación» van antes

- `tests/build.test.mjs`: la prueba de la página montada afirma el CSS (hoja opaca sin

- Evidencia: capturas 360x740 y 320x700 de verificar y finalizar (incluido el caso con aviso
